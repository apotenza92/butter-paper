### Durable storage and upgrade compatibility

The native storage correction is a development-app prerequisite, not a stable importer. It resolves the data layout once before opening the UI and keeps the existing GPUI Migration identity. Its regression uses real generated PDF bytes, TemplateLibrary records and SessionManifestStore ordered paths/active tab, deletes the render cache, then reopens the stores. A strict lossless annotation-timeline codec and leased content-addressed recovery store are implemented and deterministically tested. Normal launch binds that store and opened/generated documents publish an exact generation-checked initial recovery authority before edits are admitted; stale/closed completions and clean close clear authority. Revision-changing annotation operations synchronously replace the authoritative timeline through compare-and-swap before reporting success; ordinary failures restore the exact pre-edit timeline and selection, stale authority rolls back and blocks further edits, and an observable but unconfirmed publish keeps the post-edit state under a fail-closed ambiguous authority. Successful Save and Save As rebase recovery to the durable target and clean timeline before editing resumes, including Generated-to-Opened transition. Startup recovery discovery now precedes ordinary opening, exact-retires clean entries and fail-closed defers launch/ingress when dirty/generated/corrupt recovery exists. The persistent inbox now exposes keyboard-accessible Recover, Recover a copy and confirmation-gated Discard changes actions. Recover revalidates the opened source digest before restoring the exact dirty timeline under the existing authority; changed sources are reclassified for copy recovery. Recover a copy rematerialises the stored base in the owned generated-document store, CAS-rebinds the checkpoint, restores its timeline and opens a Save-As-required session. Discard retires only the exact authority, reloads a stale row and resumes deferred launch only after the inbox empties. An isolated current-source real-Metal SIGKILL/relaunch journey now verifies the presented inbox and accessibility tree, exact visible Rectangle/content restoration, retained dirty state and the native discard-confirmation/Cancel path. Direct store-backed tests now close ordinary edit, Undo/Redo publication, stale-authority rollback/blocking and unavailable-store rollback without checkpoint mutation.

Never point the native store directly at Electron user data: Electron recent signatures use safeStorage schemaVersion 2, while native uses the incompatible BPSIGR01 envelope and a different keyring service. Electron generated templates/defaults/colours live in Chromium localStorage and imported templates in `templates/library.json` with `{templates}`; native uses `{records,lastTemplateId,legacyBlankMigrated}`. The injected `BP_LEGACY_BLANK_SETTINGS_JSON` seam is not a complete importer. Implement a versioned, backed-up, idempotent import with rollback before changing product identity. Old migration temp stores are left untouched and are not automatically loaded from the new root.

Throwaway logic prototype · annotation architecture

Can GPUI editing stay responsive without corrupting document state?

This prototype tests whether one revisioned interaction model can preserve immutable PDF-space annotations while pointer drafts, selection, property previews, save results, and accessibility stay independent. It is a state-model experiment, not the future Butter Paper interface.

PROTOTYPE — NOT PRODUCT UI

Proposed deep modules and seams

AnnotationSession moduleSmall interface: execute one semantic command, undo, redo, and read an immutable revision.
AnnotationInteraction moduleSmall interface: reduce normalized input into a transient draft or one document command.
ToolDefinition moduleOwns canonical PDF-space geometry, exact hit tests, painting primitives, handles, properties, and PDF mapping.
PageTransform adapterMaps unrotated default-user-space PDF points through CropBox, UserUnit, rotation, zoom, and device scale.
PageAnnotationElement adapterOne custom GPUI element batches visible vector paint, spatial-index hit tests, pointer capture, and fixed-device-pixel chrome.
AccessibilityProjection adapterCreates stable, windowed annotation and handle nodes from semantic state. Pixels are never the accessibility source.

Current direct-GPUI tradeoff

Potentially better

  • The component API can encode Butter Paper's exact visual contract without fighting a third-party theme.
  • One native focus, action, and accessibility path serves the gallery and real shell.
  • Existing Geist typography, Lucide geometry, AEC icons, compact density, and selected states remain product-owned.

Observed or potentially worse

  • Butter Paper must implement and maintain every missing primitive state and transient surface.
  • The historical 800×600 GPU run clips fixed toolbar controls; responsive collapse and overflow are still required.
  • Disabled accessibility state, popup semantics, tabs, inputs, dialogs, and screen-reader behavior remain incomplete.
  • Cross-platform raster, input method editor, packaging, and PDF-domain behavior still need native tests.

Decision

Continue the owned direct-GPUI migration component by component.

Use Electron/Nova as the explicit visual and interaction contract. Keep GPUI behind a small Butter Paper component layer, then reuse each proven primitive in the state gallery and real shell. Retain custom domain elements for the PDF and annotation paths. Record better and worse user-experience tradeoffs for every family. Keep Electron as the rollback product until behavior, accessibility, document integrity, performance, packaging, updater, and platform visual gates pass.

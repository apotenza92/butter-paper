# PDF qualification corpus for the GPUI migration

Date: 2026-08-21

## Decision

Use a layered corpus. No single PDF is an adequate release gate.

1. Generate small, deterministic Butter Paper fixtures for every normal build.
2. Vendor a reviewed, attributed subset of the CC BY 4.0 veraPDF corpus for
   format-feature and safe-handling coverage.
3. Fetch two hash-pinned, public U.S. government documents for the heavy native
   and Linux GPU lanes.
4. Keep the existing Hibbeler document in a private, owner-authorized local lane.
   It is supplementary real-workload evidence, not a fixture that a contributor
   or hosted runner must possess.
5. Generate inert hostile PDFs for resource-limit and side-effect tests. Do not
   import an unreviewed exploit or fuzzing corpus into a normal app session.
6. Generate Butter Paper's annotation interoperability fixtures from source and
   compare semantic state after two save/reopen cycles.

This split gives the migration reproducible public evidence without publishing
the private Hibbeler bytes. It also avoids making a private textbook the only
way to reproduce a performance result.

## Why these lanes are distinct

| Lane | Stored where | Runs where | Main question |
| --- | --- | --- | --- |
| Deterministic core | Generator source in the repository; generated PDFs ignored | Local `pnpm check` and approved CI | Did parsing, geometry, rendering, or basic navigation regress? |
| Open format-feature | Selected PDF bytes and attribution in the repository | Local and approved CI | Can both runtimes handle representative fonts, colour, transparency, annotations, actions, attachments, and damaged structures safely? |
| Public heavy | Hash manifest in the repository; bytes in a disposable cache or approved artifact store | Native macOS/Windows and paid Linux GPU lanes | Does a large real document or huge sheet remain responsive and bounded? |
| Private Hibbeler | User-owned machine only by default; never the repository or hosted CI | Authorized local lane | Does the candidate handle the known 935-page workload? |
| Hostile/security | Generator source in the repository; generated bytes in an isolated temporary directory | Offline, disposable test process | Does invalid or active content fail safely and within limits? |
| Annotation round trip | Generator source and semantic oracle in the repository | Unit, integration, and packaged-candidate lanes | Are native annotation contracts and untouched imports preserved? |

The existing generator already produces six deterministic PDFs from owned
source and fixes its creation timestamp. Generated output is ignored and
recreated on demand ([generator](../../../scripts/generate-fixtures.mjs),
[fixture policy](../../../tests/fixtures/README.md)). The PDF package already
has strong source-generated round-trip coverage for 19 Butter Paper markup
kinds, native Bluebeam-shaped groups, replies, appearance streams, image and
snapshot payloads, fonts, measurements, and untouched imported annotations
([PDF tests](../../../packages/pdf/src/index.test.ts)). The corpus work should
promote these contracts into named qualification fixtures rather than replace
them with third-party files.

`pass` and `fail` in these names mean conformance to the named archival
profile. They do not mean that a general-purpose viewer must accept or reject
the file. For Butter Paper, the expected result is:

- every case finishes before its limit without a crash, hang, unbounded memory,
  file write, process launch, or network request;
- conforming visual cases open and paint their expected single page;
- an allowlisted recoverable case may open with a stable warning;
- a rejected case reports the stable `invalid-pdf`, `unsupported-feature`,
  `password-required`, or `resource-limit` category;
- Electron and GPUI must agree on success versus error category at cutover,
  unless a reviewed GPUI difference is stricter and safer;
- actions and attachments remain inert. PDF can describe JavaScript, URI,
  submit-form, and application-launch actions, so "we do not expose this UI"
  is not by itself a security test
  ([Adobe action documentation](https://opensource.adobe.com/dc-acrobat-sdk-docs/library/pdfmark/pdfmark_Actions.html)).

Do not use `qpdf --check` as the only oracle. qpdf documents that status 0 means
no detected syntax errors or warnings, status 2 means errors, and status 3 means
warnings; it also states that it cannot detect every PDF problem
([qpdf CLI](https://qpdf.readthedocs.io/en/stable/cli.html)). Use it as one
structural assertion for valid outputs, alongside app behavior and semantic
inspection.

## Public heavy corpus

### `nasa-apollo-summary-526-v1`

- Source record: [NASA NTRS 19750013242](https://ntrs.nasa.gov/citations/19750013242)
- Bytes: `27,842,805`
- Pages: `526`
- SHA-256: `68d0f3bb93fd1c4e4f3adf99d483e9161f14293a311e25aa6c31241bbbb84049`
- PDF version: 1.4; linearized; unencrypted.
- Rights: the NTRS record marks the distribution as public and the copyright as
  a U.S. Government work with public use permitted.
- Purpose: a long, real scanned engineering program report for open, thumbnail,
  page-jump, continuous-scroll, cache, search/text-availability, and memory
  behavior.

Expected result: report 526 pages; first page becomes visible; visit the fixed
normalized page sequence without stale surfaces; scroll continuously for 50
viewports; return to page 1; keep page and thumbnail caches within the declared
budgets; close without a leaked worker or child process.

### `usgs-usa-geology-sheet-v1`

- Source page: [USGS Online Files for USA Geology](https://pubs.usgs.gov/dds/dds11/kb.html)
- Source PDF: [USA Geology map](https://pubs.usgs.gov/dds/dds11/USA_Geology_KB_Map.pdf)
- Bytes: `180,360,864`
- Pages: `1`
- Page size: `5589 x 3524` points.
- SHA-256: `f058179e193ccbc15ca662feff3554102f64ff2114436a5ce6116d6fa5d2a6e2`
- PDF version: 1.3; not linearized; unencrypted.
- Rights: USGS states that its authored or produced reports and information are
  in the U.S. public domain, with attribution requested; it also warns that
  individually marked third-party material can have separate rights
  ([USGS copyright guidance](https://www.usgs.gov/faqs/are-usgs-reportspublications-copyrighted)).
- Purpose: a 180 MB, unusually large single sheet that stresses file loading,
  decoding, raster dimensions, pan, zoom, cancellation, cache eviction, and
  memory limits differently from a long book.

Expected result: show a fit-page surface; pan all four quadrants at 400%; run the
fixed zoom sequence through 1600% without allocating an unbounded full-page
raster; cancel superseded work; return to fit-page; and recover memory to the
declared post-operation budget.

The hashes above were verified from the official download URLs on 2026-08-21.
The source URLs are not the identity. A fetch script must download to a temporary
file, check byte count and SHA-256, and only then move it into a content-addressed
cache. A mismatch fails closed and requires a reviewed corpus-version update.
Do not silently accept updated government-hosted bytes.

Do not add the two heavy PDFs to normal git history. An approved manual workflow
can use an immutable artifact mirror after its source, rights note, attribution,
and hash have been reviewed. Otherwise, fetch from the official source and use a
cache keyed by the expected hash.

## Private Hibbeler lane

Use the neutral ID `private-hibbeler-935-v1` in commands and reports. The current
protocol identifies these bytes:

- SHA-256: `f4ef16810f9b68dad7fe55d2c28028a3e08a3a6ee39193c565ac96713bc0b6a6`
- Bytes: `127,532,074`
- Pages: `935`

Policy:

1. The owner must confirm that the copy is lawfully possessed and may be used
   for local application testing. Access to a machine does not provide that
   confirmation.
2. Keep the PDF on the owner-controlled Mac by default. Pass its path through an
   environment variable or local ignored configuration. Never add the path,
   title, bytes, page images, extracted text, or thumbnails to git, CI artifacts,
   logs, screenshots, prompts, or issue comments.
3. Reports contain only the neutral corpus ID, SHA-256, byte count, page count,
   scenario metrics, and non-content error categories. Scrub absolute paths and
   subprocess diagnostics before a report leaves the machine.
4. Do not upload these bytes to hosted CI or a paid GPU system. If a later task
   needs remote private-document testing, require explicit authorization for
   that named host and transfer, plus rights confirmation. Use an encrypted
   authenticated transfer, a private ephemeral volume, no snapshots/backups,
   no agent-readable content output, a predeclared time-to-live (TTL), and
   verified deletion before destroying the host.
5. A Hibbeler failure blocks the private-workload gate. A missing Hibbeler file
   is `blocked`, not `failed`, and does not invalidate the reproducible public
   corpus result.

The current protocol exposes the private filename in tracked documentation
([performance protocol](../performance/protocol.md)). Replace it with the neutral
corpus ID when implementing this policy.

## Malformed and security corpus

Generate inert probes from owned source. Each probe must have a descriptive ID,
SHA-256, size, generation recipe, expected error or recovery category, wall-time
limit, resident-set-size (RSS) limit, and permitted side effects. Include:

- truncated header, trailer, cross-reference table, and object stream;
- invalid offsets, stream lengths, filters, object references, and page boxes;
- cyclic and deeply nested page/object graphs;
- a compressed stream that expands beyond the configured decode limit;
- huge declared image dimensions and a huge page box;
- zero-page and excessive-page-count documents;
- invalid, unsupported, and password-required encryption cases;
- incremental updates with orphaned and replaced objects;
- document-open and annotation actions for JavaScript, URI, `SubmitForm`, and
  `Launch`, using inert sentinel targets;
- an embedded sentinel file that must not be extracted automatically;
- annotation appearances with missing, recursive, invalid, and oversized
  resources.

Expected outcome rules:

- The parser may recover only cases explicitly marked `recover` in the manifest.
- Every other malformed probe must return one stable error category and leave
  the shell usable for the next document.
- No probe can create a file outside its disposable output directory, open a
  socket, spawn a non-allowlisted process, launch another application, or retain
  its content after the test process exits.
- Every probe has a short wall-time and RSS ceiling. A timeout, signal, panic,
  renderer death, watchdog kill, or ceiling breach is a failure, not an expected
  rejection.
- Run this lane offline with an empty disposable home, user-data directory, and
  output directory. Do not give it cloud credentials, SSH keys, desktop tokens,
  a private corpus, or a user's normal interactive app state.

Do not commit a mutable OSS-Fuzz or qpdf "latest corpus" archive. qpdf's own
maintainer documentation points to a mutable `latest.zip`, which is useful for
ad hoc discovery but not a stable qualification identity
([qpdf maintainer documentation](https://github.com/qpdf/qpdf/blob/main/README-maintainer.md)).
When a fuzzer finds a useful regression, minimize it, confirm its provenance or
regenerate an equivalent owned probe, assign a new corpus ID, and review it
before adding it to this manifest.

## Annotation round-trip oracle

Use `bp-annotation-all-v1` and `bp-annotation-density-v1`; do not depend on a
private real-world marked-up document for correctness. The existing domain model
defines the safe imported metadata and all supported markup variants
([document model](../../../packages/core/src/document.ts)).

For each runtime, perform:

1. Open the generated source PDF and record page geometry and native annotation
   inventory.
2. Import markups and compare a canonical JSON representation.
3. Save as a new path. Never overwrite the oracle.
4. Run `qpdf --check`; status 0 is required for an output expected to be fully
   valid. Treat status 3 as a failure unless the exact warning is reviewed and
   allowlisted.
5. Reopen, compare canonical JSON, and render fixed annotation crops.
6. Edit one member of each compound type, delete another, add one of each
   supported type, and save again.
7. Reopen a second time and repeat semantic and visual comparisons.

Canonical JSON must include page/index, markup kind and stable logical ID,
geometry in unrotated PDF points, appearance, text/rich-text runs, measurement
scale and units, image digest and MIME type, native subtype/intent, group and
reply links, author/status/date fields, flags, and the fingerprint of untouched
imported objects. Sort arrays by stable IDs and normalize floating-point values
to the precision used by the writer.

Do not compare whole output-file hashes. Valid PDF writers can change object
numbers, cross-reference layout, compression, generated IDs, and modification
timestamps without changing the document. Compare canonical semantics, required
native dictionary contracts, qpdf status, page renders, and preservation
fingerprints. Exact PNG hashes are suitable only within the same renderer,
operating system, font set, colour profile, and scale. Electron-to-GPUI render
comparison must use reviewed crops and a perceptual threshold plus manual review.

## Performance protocol extension

Keep the current 1200x800 light-theme window, 100 ms process-tree sampling,
cold per-process cache, raw event retention, and matched Electron/GPUI scenario
contract ([current protocol](../performance/protocol.md),
[runner contract](../performance/README.md)). Extend it as follows.

### Scenarios

Run these on `private-hibbeler-935-v1` and
`nasa-apollo-summary-526-v1`:

- empty shell;
- cold open to first visible page;
- page navigation;
- zoom;
- continuous scroll for 50 fixed viewport deltas;
- thumbnail sweep from start to end and back;
- 400% pan through a fixed rectangular path;
- create/edit/delete 100 deterministic markups, save as, close, and reopen;
- a 15-minute mixed-operation soak with memory slope and post-close process
  cleanup.

For a document with `N` pages, use this normalized navigation sequence, rounded
up and clamped to `1..N`:

`N, 0.08N, 0.72N, 0.25N, 0.90N, 0.50N, 11, 0.958N, 0.33N, 1`

This reproduces the current Hibbeler sequence while making the public NASA
document comparable. Use the existing zoom sequence:

`100, 200, 400, 800, 1600, 400, 100, 800, 200, 100, 1200, 100`

Run the USGS sheet for cold open, fit-page, zoom, pan, cancellation, cache, and
memory scenarios. Do not run page-navigation or thumbnail-count claims on a
one-page file.

### Comparison and acceptance

- Compare Electron and GPUI only on the same host, operating system, display,
  GPU, driver, refresh rate, scale factor, power state, fixture bytes, window,
  cache state, and scenario implementation. Do not compare a Linux GPUI number
  with a macOS Electron number.
- Alternate implementation order. Preserve every failed and timed-out
  iteration. Run five independent processes for development evidence and at
  least 20 successful, alternating pairs for a release decision.
- Report median, p95, p99, maximum, and counts above 8.33, 16.67, and 33.33 ms
  for interaction and frame intervals. Also report CPU, process-tree RSS, GPU
  memory when available, cache count/bytes/hits/misses, decoded surface sizes,
  and post-close memory.
- Use a paired bootstrap confidence interval for the GPUI/Electron ratio. The
  accepted policy is no statistically significant p95 regression. Report both
  the ratio and interval; do not turn an underpowered result into "equal."
  Predeclare a practical guardrail after the first clean matched baseline.
- Keep PDF raster/decode timing separate from application-frame and input
  latency. The current Electron path uses PDF.js while the spike uses Poppler,
  so the result is end-to-end product evidence, not a framework-only benchmark.
- A frame callback is not proof of display presentation. Use native presentation
  tooling for the final 120 Hz macOS gate and equivalent native tools for
  Windows and Linux.

### Efficient paid Linux GPU lane

Build and validate the candidate and fetch/hash the public corpus before leasing
the GPU host. The task agent estimates a TTL and declares an absolute maximum
before provisioning. Upload only the public corpus and candidate artifacts.
Warm the host once, then run alternating Electron/GPUI pairs for all public
scenarios in one lease. Download raw reports, validate their completeness and
hashes, and destroy the droplet and volumes immediately when complete. An early
finish is not success by itself: require the expected report count, scenario
completion event, and raw samples before teardown.

The paid Linux GPU lane never receives Hibbeler under the default policy.

## Evidence manifest and reporting policy

Every corpus item has a machine-readable manifest entry with:

- corpus ID and corpus schema version;
- SHA-256 and byte count;
- page count, page boxes, rotations, encryption state, and expected features;
- source URL and source revision where applicable;
- license or rights statement and required attribution;
- storage class: `generated`, `vendored-open`, `fetched-public`, or
  `private-local`;
- allowed test lanes;
- expected open/error category, semantic oracle version, and visual crop IDs;
- time, RSS, decoded-pixel, cache-byte, and output-size ceilings.

Every result records:

- corpus ID and verified identity, never only a filename;
- source revision, dirty-state flag, executable hash, runtime type
  (development or packaged), renderer and dependency versions;
- host ID, operating system and kernel, architecture, CPU, physical memory,
  GPU and driver, display resolution/refresh/scale, theme, colour profile,
  power state, and thermal state where available;
- scenario version, iteration, implementation order, cold/warm cache state,
  start/end timestamps, timeout and resource limits;
- raw milestones, process samples, errors, and completion state;
- aggregate method and confidence interval.

Store normal public raw results in an ignored results directory during
development and attach them only to an approved issue, pull request, or release
gate when requested. Store private-lane raw results locally. Publish only the
scrubbed aggregate from that lane. A stale report or screenshot remains
historical evidence and cannot satisfy a current gate.

## Gate policy

- **Every required deterministic gate:** generated core fixtures, generated
  annotation semantics, and the small open format-feature subset.
- **Manual native or release-candidate gate:** all deterministic fixtures,
  public heavy files, hostile cases, annotation density/save/reopen, and the
  performance scenarios on each supported operating system.
- **Paid Linux GPU gate:** public corpus only, with matched Electron and GPUI
  runs on the same leased host.
- **Private local gate:** Hibbeler on an authorized owner-controlled machine.
- **Cutover:** no lost content or corrupt save, every required public lane
  passes, the private lane passes or is explicitly waived as unavailable, and
  GPUI has no statistically significant p95 regression under the matched
  protocol. A blocked private file cannot be reported as a pass.
